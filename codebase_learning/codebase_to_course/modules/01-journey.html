What actually happens when you type /apply

AI Job Search is a free toolkit built on top of Claude Code. It turns Claude Code into a personal job-application team: it checks whether a job posting is a good fit for you, drafts a tailored two-page CV and cover letter, and preps you for interviews. A geophysicist built it to land his own AI engineering job — then open-sourced it.

This module follows one command through the whole system, start to finish, so you can see the machinery behind the result.

The key insight: it's just a checklist

Here's the part that surprises most people. apply.md isn't a hidden program or a black box — it's a Markdown file, the same kind of plain-text file you'd use for a to-do list. Claude Code reads it top to bottom and follows it like a recipe.

CODE 

# /apply - Drafter-Reviewer Job Application Workflow

You are orchestrating a two-agent job application workflow. The job posting is provided below as `$ARGUMENTS` (either a URL or pasted text).

Follow these steps **exactly in order**. Do not skip steps.

**Token-efficiency rules for this workflow:**
- Never re-Read a file whose contents are already in your context from an earlier step. If you read it in Step 1, it is still available in Step 2.
- When dispatching the reviewer agent, pass draft content **inline in the agent prompt** rather than asking the agent to Read files you already have in memory.
- Run the full verification checklist exactly once, at the end (Step 6). The reviewer focuses on content critique, not verification.
- Step 5 (compile and inspect PDFs) is mandatory and non-skippable...
PLAIN ENGLISH

This is the title of the recipe, and a reminder that two AI helpers are involved: one drafts, one reviews. Whatever you pasted after /apply — a link or raw text — gets stored in a placeholder called $ARGUMENTS.

A firm rule: go through the steps in order, don't improvise, don't skip ahead.

These are cost-saving habits: don't make Claude re-read a file it already has in memory, and don't waste a second AI's time re-fetching things the first one already found.

Save the big "check everything" pass for the very end, once, instead of repeating it after every step.

Some steps are flagged as unskippable because skipping them causes real, hard-to-spot problems later — like a CV that looks fine in the source file but renders broken.

💡
There's no hidden server

No database, no login, no cloud backend running somewhere. The "code" here is mostly plain-English instructions that an AI reads and follows, step by step, in a folder on your own computer.

Step 0: the very first thing Claude does

Before anything else, Claude has to figure out what you actually gave it.

CODE 

## Step 0: Parse Input

- If `$ARGUMENTS` looks like a URL, use `WebFetch` to retrieve the job posting content.
- If it is pasted text, use it directly.
- Extract: **company name**, **role title**, **department** (if mentioned), **location**, and **language** of the posting (Danish or English).
- Store these for use throughout the workflow.
PLAIN ENGLISH

Claude checks: does what you gave it look like a web link?

If it's a link, Claude uses a tool called WebFetch to go open that page and read it. If you pasted the job description directly instead, Claude skips fetching and just reads what you typed.

Either way, Claude then pulls out the specific facts it'll need later: company name, job title, department, location, and whether the posting is in Danish or English.

Those facts get kept in Claude's memory for every later step — nobody has to re-explain them.

Quick check

Three scenarios. Think it through before you pick.

You paste the raw text of a job posting instead of a URL into /apply. What does Step 0 do differently?

Why does apply.md say "do not skip steps" but also "run the verification checklist exactly once, at the end"?

You want /apply to also translate the CV into French. Is that a new skill file, or a change to apply.md's existing steps?

What this means for you

/apply is really an ordered checklist that Claude executes, one line at a time. Because it's just a Markdown file, you can open it, read every step, and even edit it yourself — no programming required.

Want Claude to skip a step this one time, or add a step of your own? You can just tell it. It's your checklist.
