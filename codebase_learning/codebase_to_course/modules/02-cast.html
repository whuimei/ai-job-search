Meet the Cast

Skills, commands, subagents, and CLI tools — the four kinds of files behind every AI job-search action.

In Module 1 you watched /apply fetch a job posting. That fetching step didn't happen by magic. It happened because a specific kind of file told Claude exactly how.

This module meets the four kinds of files that make up the whole cast. Think of the repo as a theater company running backstage: every file is a role, and every role behaves differently once the curtain goes up.

Four Roles, Four Jobs

A command is the script cue-card an actor is handed at showtime: "say this line now." A skill is the actor's full training and standing instructions, reusable across many shows.

A subagent is a stunt double: brought in for one dangerous scene, given a fresh briefing, and sent home when the scene wraps. A CLI tool is a stagehand who only does one physical task — raise the curtain — when cued, and doesn't act at all.

🎬

Command

A cue-card triggered by typing /name. One-shot: fires now, then it's done.

File: .claude/commands/interview.md

You'd say: "add a new command for /outcome"

📖

Skill

Standing reference knowledge Claude loads automatically when it's relevant — not something you trigger by name.

File: .claude/skills/job-scraper/SKILL.md

You'd say: "that belongs in a skill's reference file"

🎭

Subagent

A second, temporary Claude with fresh memory, spun up for one scene, then dismissed.

Example: the /apply reviewer agent

You'd say: "spin up a subagent to review this with fresh eyes"

⚙️

CLI Tool

A plain program with flags. It executes; it doesn't think or judge.

File: .agents/skills/linkedin-search/cli/src/cli.ts

You'd say: "run the linkedin-search CLI with a location flag"

Inside a Skill's Training Sheet

Skills are the role with real YAML frontmatter. Commands are just plain markdown starting with a heading — no frontmatter needed. Here's the real training sheet for the freehire-search skill.

CODE 

---
name: freehire-search
version: 1.0.0
description: >
  Use this skill to search live software / tech / data / engineering job listings
  across many countries and markets (and remote) via the freehire.dev aggregator's
  public API, or to look up a specific posting. It aggregates roles from ~50 ATS
  platforms into one schema, so a single skill covers many markets — but its faceted
  filtering (skills, category, seniority) is tuned tech-first, so scope triggers to
  technical roles. Trigger phrases: find a tech job, software job search, developer
  jobs, engineering vacancies, data/ML jobs, DevOps roles, remote developer jobs,
  "are there any <tech role> jobs in <place>", look up this freehire job posting.
context: fork
allowed-tools: Bash(bun run .agents/skills/freehire-search/cli/src/cli.ts *)
---
PLAIN ENGLISH

name is the skill's ID — how Claude and the file system refer to it internally.

description is the trigger list: the phrases that make Claude decide "this skill is relevant, load it now." This is literally how Claude discovers what tools exist for a given request.

Every scenario listed here (job search, ATS lookup) teaches Claude when to reach for this skill instead of guessing.

allowed-tools is a safety fence: this skill can ONLY run this one specific command, nothing else — it can't suddenly start deleting files or browsing the web.

💡
Good to know

A second real example, .claude/skills/job-scraper/SKILL.md, restricts its allowed-tools to Read, Write, Edit, Glob, Grep, Bash(bun --version), Bash(bun run .agents/skills/*/cli/src/cli.ts *), WebFetch, WebSearch, Agent, AskUserQuestion — a wider fence, because scraping needs to read files, call multiple CLIs, and even hand off to a subagent.

The Stagehand Doesn't Improvise

A CLI tool has its own help text, written by a human, not generated by AI judgment. Here's the actual header from the LinkedIn search tool.

CODE 

const HELP = `linkedin-cli — search jobs on LinkedIn (any country/region, plus remote)

USAGE
  bun run src/cli.ts search --location "<place>" [flags]
  bun run src/cli.ts detail <id|url> [--format json|plain]
PLAIN ENGLISH

This text is hard-coded. The tool doesn't "decide" what to say — a human wrote these exact words once.

"USAGE" spells out the fixed commands you can run and nothing else.

A flag like --location is a fixed switch; the tool reads it and follows the rule, it doesn't reason about it.

When this CLI hits an error, it exits with an error code and a canned message. It isn't "thinking" about the failure — it's just reporting one, the way a smoke alarm beeps instead of explaining the fire.
